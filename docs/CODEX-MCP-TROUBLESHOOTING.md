# Codex MCP troubleshooting

## Plugin-generated MCP servers

Codex MCP servers are not only defined by manual entries in `~/.codex/config.toml`.
Plugins can declare MCP servers through their own bundle metadata.

A symptom of this case is:

```
MCP startup incomplete (failed: <server>)
<server> MCP server is not logged in
```

while:

- `codex mcp list` does not show a manually configured server;
- `~/.codex/config.toml` does not contain the server;
- starting Codex with plugins disabled does not reproduce the issue.

## Diagnosis

Check plugin bundles before modifying configuration or deleting cache files.
A plugin can declare an MCP server in its `.mcp.json` bundle metadata.

Example resolution path:

1. Identify the plugin bundle declaring the MCP server.
2. Keep the plugin installed if other capabilities are required.
3. Disable only the generated MCP server through the persistent Codex configuration.
4. Restart Codex and verify a fresh process.

## Example

For `cloudflare-api` generated by the Cloudflare plugin bundle:

```toml
[mcp_servers.cloudflare-api]
url = "https://mcp.cloudflare.com/mcp"
enabled = false
```

This keeps the plugin available while preventing automatic MCP startup.

## Constraints

Do not:

- remove generated plugin cache as a permanent fix;
- disable all plugins to hide one failing MCP;
- replace the fix with aliases or wrappers;
- edit generated plugin metadata as the source of truth.

The persistent configuration override must remain external to the generated bundle so plugin refreshes do not remove the operator decision.
